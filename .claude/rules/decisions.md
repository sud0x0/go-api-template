# Settled decisions

Deliberate trade-offs already made in this codebase, each with a one-line
rationale and a code citation. **Do not relitigate these unless the user
explicitly asks.** A proposal that contradicts an entry here is a finding to
flag against this file, not a default to adopt. When you add a new deliberate
trade-off, record it here so the next reviewer (human or agent) doesn't re-open it.

| # | Decision | Rationale | Evidence |
|---|---|---|---|
| 1 | **Offset AND cursor pagination coexist** on `GET /api/v1/logs`. | Offset is simple for shallow/UI paging, and cursor (keyset) is constant-cost and insert-stable for deep/unbounded walks. Both keep their place. | [`userlog_handler.go` ListLogs](../../internal/userlog/userlog_handler.go), [`userlog_repository.go`](../../internal/userlog/userlog_repository.go) |
| 2 | **Response-shape asymmetry kept** for backwards compatibility: offset-mode returns a **bare array** `[…]`, and cursor-mode returns the wrapped `CursorPage` `{"logs":[…],"next_cursor":"…"}` (`next_cursor` omitted on the last page). | Changing the offset response to an object would break existing clients. The asymmetry is documented in the OpenAPI spec. | [`userlog_model.go` `CursorPage`](../../internal/userlog/userlog_model.go) |
| 3 | **Cursors are opaque but UNSIGNED**: base64url of `(date_and_time, id)`, no HMAC. | Every query stays `user_id`-scoped, so a forged cursor cannot cross user boundaries. It can only reposition within the caller's own rows. Signing would add key management for no security gain. Malformed cursors are rejected (strict RFC3339Nano + UUID) before any SQL. | [`userlog_cursor.go`](../../internal/userlog/userlog_cursor.go) |
| 4 | **Rate limiting is edge-first.** The app limiter is an opt-in fallback (`RATE_LIMIT_RPM`, default `0` = not even registered), keyed by client IP, counters in-memory **per instance**. | The primary control belongs at the LB / gateway / WAF. Per-instance counters mean the effective global limit is `RATE_LIMIT_RPM × replicas`. | [`cmd/api/main.go`](../../cmd/api/main.go) |
| 5 | **The internal admin router keeps chi's plain-text defaults** (no JSON envelope on its 404/405). | `:METRICS_PORT` is an operator-only surface with no auth, restricted at the infra layer. The single-envelope rule is a *public-API* contract. | [`cmd/api/main.go` `internalRouter`](../../cmd/api/main.go) |
| 6 | **Batch inserts are sequential per-row inside one transaction**: a loop of `txRepo.createLog`, not `pgx.Batch`. | Atomicity (any failure rolls back the lot) is the requirement. `pgx.Batch` is a round-trip optimisation deferred until a measurement shows it's needed. | [`userlog_service.go` `createLogs`](../../internal/userlog/userlog_service.go) |
| 7 | **OpenTelemetry is adopted for inbound traces and metrics (OTLP). Only the OUTBOUND httpclient's own tracing stays deferred.** | Inbound spans (`otelhttp` on the public router) and all metrics now export via OTLP, see #15. The outbound `internal/httpclient` still uses the stdlib transport, so wrapping it with `otelhttp.NewTransport` for client spans is the one remaining documented swap, not a gap. | [`internal/httpclient/httpclient.go`](../../internal/httpclient/httpclient.go), [`internal/observability/observability.go`](../../internal/observability/observability.go) |
| 8 | **`metrics.New()` builds instruments from the global OTel MeterProvider and is constructed once from main, but it is no longer call-once-or-panic.** | OTel dedupes instruments by name within a meter, so a second call would not panic the way the old `prometheus.MustRegister` did. Tests isolate by building against a fresh `ManualReader`-backed meter rather than the global provider. | [`internal/metrics/metrics.go`](../../internal/metrics/metrics.go) |
| 9 | **Readiness cache: TTL 2s, ping on a `context.WithoutCancel` context, never cache `context.Canceled`.** | A flood of probes collapses to one DB ping per window. Detaching cancellation stops a client aborting `/readyz` mid-ping from poisoning the shared result. A genuine `DeadlineExceeded` *is* cached (real DB signal), a `Canceled` is not. | [`internal/db/health_cache.go`](../../internal/db/health_cache.go), [`cmd/api/main.go` `readinessCacheTTL`](../../cmd/api/main.go) |
| 10 | **The UUID user-ID contract is enforced at the single READ point** (`shared.UserIDFromContext` canonicalises and rejects non-UUIDs as 401). `WithUserID` stays a plain setter. | One enforcement point means a second writer can't bypass validation. Validating at write would let a different writer skip it. `repoMaxUserIDLength` (64) is retained as defence-in-depth for non-handler callers. | [`internal/shared/identity.go`](../../internal/shared/identity.go), [`userlog_repository.go`](../../internal/userlog/userlog_repository.go) |
| 11 | **`WriteTimeout` MUST be greater than `RequestTimeout`**, validated at startup. | A write window shorter than the handler timeout silently truncates slow responses (surfaces as "connection reset"). Fail fast instead of shipping it. | [`internal/config/config.go` `Config.validate`](../../internal/config/config.go) |
| 12 | **Single-statement repository methods are never wrapped in a transaction.** | A lone statement is already atomic. `WithTransaction` would add a round-trip for nothing. Reach for it only when two or more statements must commit/roll back together. | [`userlog_service.go`](../../internal/userlog/userlog_service.go) |
| 13 | **Authentication and authorisation are implemented as a two-layer model wired at the `r.Route("/api/v1", …)` seam.** Layer 1 is OIDC token validation (go-oidc, in-process). Layer 2 is OPA function-level authorisation (sidecar over REST). Both are opt-in and OFF by default so the template still boots with no IdP for local dev. The `WithUserID`/`UserIDFromContext` seam is unchanged. The auth middleware writes through it. | The template ships the actual middleware (not just the seam) so adopters get a working resource-server model, while keeping the IdP and policy swappable via config and the role boundary. Disabled-by-default keeps local dev zero-setup. See #16–#19 for the resource-server scope, the OPA-over-REST choice, the iss\|sub→UUID mapping, and what stays the adopter's responsibility. | [`cmd/api/main.go`](../../cmd/api/main.go), [`internal/middleware/auth_middleware.go`](../../internal/middleware/auth_middleware.go), [`internal/middleware/authz_middleware.go`](../../internal/middleware/authz_middleware.go), [`internal/shared/identity.go`](../../internal/shared/identity.go) |
| 14 | **OWASP ASVS 5.0.0 Level 2 is the security verification bar** (L1 included by definition, L3-only out of scope). The official machine-readable CSV is the committed upstream source, its plain-text rendering `asvs-5.0.0.txt` is the greppable artefact, and the applicability map is committed alongside them under the security skill. With auth now implemented (#13), the resource-server requirements of **V9** (self-contained tokens) and **V10.3/V10.5** (OAuth resource server, OIDC client identity) are per-requirement `met` rows citing the middleware and its tests. The authorization-server and browser-client requirements (V10.1/V10.2/V10.4/V10.6/V10.7, nonce/back-channel-logout) stay `n/a` as the adopter IdP's or frontend's responsibility, and V6/V7 remain largely IdP-owned (the resource server validates tokens, it runs no login or session mechanism). | The bar is written down so reviews are repeatable and gaps are tracked, not re-derived. Committing the standard makes the review self-contained. The honest met/n-a split stops the map from claiming authorization-server controls the resource server does not implement. | [`.claude/skills/security-review/references/asvs-map.md`](../skills/security-review/references/asvs-map.md), [`.claude/skills/security-review/SKILL.md`](../skills/security-review/SKILL.md) |
| 15 | **Observability is OpenTelemetry. Traces and metrics export over OTLP/HTTP to a Collector that re-exposes Prometheus. Logs stay on stdlib slog JSON to stdout, correlated to traces by injected `trace_id`/`span_id`.** | One vendor-neutral model, chosen at the Collector, keeps the app cheap (no in-process batching beyond the SDK queue, no scrape endpoint on the app). The OTel Go logs SDK is still beta, so logs are NOT moved in-process and stay on slog. OTLP transport is HTTP on port 4318 for a lighter dependency tree than gRPC. Core `go.opentelemetry.io/otel` is v1.44.0. Semconv is the v1.41.0 package (the highest shipped in that core, at or below the targeted spec 1.43.0). | [`internal/observability/observability.go`](../../internal/observability/observability.go), [`cmd/api/main.go`](../../cmd/api/main.go), [`deploy/otel-collector-config.yaml`](../../deploy/otel-collector-config.yaml) |
| 16 | **The app is an OAuth2 RESOURCE SERVER, not an authorization server and not a browser OIDC client.** It receives a Bearer access token in the `Authorization` header, validates it with go-oidc against the IdP's discovered JWKS, and enforces access. The login redirect, code exchange, PKCE, `state`/`nonce`, redirect-URI registration, and refresh rotation are NOT implemented. They belong to the adopter's IdP and frontend (see #19). | A template cannot guess an adopter's login UX, but every adopter's API must validate the token it is handed. Shipping only the resource-server half is the reusable, non-presumptuous slice. go-oidc is the validation library because it wraps discovery + `RemoteKeySet` (JWKS fetch/rotate) and refuses token-supplied `jku`/`x5u`/`jwk`. `oidc.InsecureIssuerURLContext` is deliberately NOT used (exact issuer match, ASVS V10.5.3). | [`internal/middleware/auth_middleware.go`](../../internal/middleware/auth_middleware.go), [`internal/config/config.go` `OIDCConfig`](../../internal/config/config.go) |
| 17 | **Authorisation is an OPA sidecar consulted over its REST Data API, fail-closed, FUNCTION-LEVEL only.** The middleware POSTs `{input:{subject,roles,action,resource,method}}` to `OPA_URL/OPA_DECISION_PATH` and allows ONLY on an explicit `result==true`. Any error (timeout, non-200, malformed body, missing result) denies with 403. The repository's `WHERE user_id = $N` SQL scoping stays as the ROW-OWNERSHIP layer and is NOT moved into OPA. | REST (not gRPC, not the Envoy external-authz variant) because the app calls OPA directly, so the standard `openpolicyagent/opa` image suffices with no Envoy in the path and a lighter dependency tree. Fail-closed is the security-critical default: an OPA outage becomes a visible 403, never an authorisation bypass. Keeping row ownership in SQL is defence in depth. OPA answers "may this role call this endpoint", the SQL answers "may this user see this row". Collapsing them would put row filtering behind a network hop and a policy edit. | [`internal/middleware/authz_middleware.go`](../../internal/middleware/authz_middleware.go), [`deploy/opa/policy.rego`](../../deploy/opa/policy.rego), [`compose.dev.yaml`](../../compose.dev.yaml) |
| 18 | **External identity maps to the internal UUID via `UUIDv5(fixed-namespace, iss\|sub)`, computed in the auth middleware, no lookup table.** IdP roles/groups map to internal roles at the same boundary (`mapClaimsToRoles`), so the policy is written against internal role names. | The `user_id` column is `UUID NOT NULL` but an IdP `sub` is often not a UUID (`auth0\|12345`, an email). A deterministic v5 derivation is reproducible across restarts and replicas with zero infrastructure, and including `iss` stops two IdPs colliding on the same `sub`. It is documented as swappable: a real deployment may keep a `users` table mapping `(iss,sub)→id` and resolve it in the middleware before `WithUserID`. `UserIDFromContext` still enforces the UUID shape at the single read point (#10). | [`internal/middleware/auth_middleware.go` `MapSubjectToUUID`](../../internal/middleware/auth_middleware.go) |
| 19 | **Authorization-server and browser-client concerns are explicitly OUT OF SCOPE: the adopter's IdP and frontend own them.** PKCE, redirect-URI allowlisting, the `state`/`nonce` parameters, authorization-code exchange, refresh-token rotation, consent, and back-channel logout are not implemented and are commented as such (not forgotten). Token storage is the client's concern. The template only documents that browser forks must not use `localStorage`. | These are properties of the login flow, which a resource server never runs. Implementing them would mean guessing the adopter's IdP and UX. The ASVS map records each as `n/a` with the reason "authorization server / OIDC client responsibility" rather than as a gap. | [`internal/middleware/auth_middleware.go`](../../internal/middleware/auth_middleware.go), [`.claude/skills/security-review/references/asvs-map.md`](../skills/security-review/references/asvs-map.md) |
